# 고객표준여정(CJM) – 업무프레임워크(SBF) 연계 구조 (안)

> 작성: CX팀 / 2026-06-10 / 보고 대상: 담당 임원
> 목적: CJM과 SBF를 연결·관리하는 전체 구조와 추진 방향 공유

---

## 1. 추진 배경

- 전사 고객 경험의 표준이 되는 **고객표준여정(CJM, L1~L4)** 과 여정별 KPI를 현업 의견으로 확정 완료
- 채널·NOVA(기간계 BO) 직원 업무는 별도로 **SBF(SKT Business Framework, v2.0)** 로 정의 — 약 870개 업무 목록
- 현재 두 체계는 **각각 따로 관리** → 고객이 겪는 경험(CJM)과 그것을 처리하는 업무·시스템(SBF)이 단절
- 임원 요청: **CJM과 SBF를 연결·매핑하여 통합 관리** (예: 고객 "미납 처리" 단계 → SBF "미납 청구 조회/처리" 업무 → BSS 화면까지 추적)

## 2. 핵심 개념 — 두 관점을 하나의 사슬로

- **CJM = 고객 관점** : "고객이 무엇을 경험하고, 무엇을 하려는가"
- **SBF = 업무·시스템 관점** : "그 경험을 직원·시스템이 어떤 업무로 수행하는가"
- 두 관점을 연결하면 다음 사슬이 완성됨

```
[CJM 고객단계]  ─────▶  [SBF 업무]  ─────▶  [BSS 화면/시스템]
  미납 처리            미납 청구 조회·처리        해당 BSS 화면
 (고객이 겪는 것)      (직원이 수행하는 업무)     (업무가 돌아가는 시스템)
```

## 3. 연결이 이미 절반은 준비되어 있음 (중요)

- **SBF는 내부에 이미 "여정 축"을 보유** : SBF 1Depth에 `1.탐색 · 2.회원·계정 · 3.계약·개통 · 5.이용·변경 · 7.청구·수납 · 8.채권·조정 · 9.해지·잔존` 등 번호형 단계 존재 → CJM L1과 평행 구조
- **SBF → BSS 화면 연결은 v2.0에 이미 존재** : `SSF(L3)-화면 맵핑` 시트에 실제 BSS 화면코드(UI Pgm ID) 약 1만 건 매핑 완료
- **KPI 레벨 연결도 일부 진행** : CJM KPI 출처에 "NOVA SBF KPI"가 이미 반영됨
- ▶ **결론 : 신규로 구축할 것은 "CJM ↔ SBF" 연결 고리 단 하나.** BSS 연결은 자동으로 따라옴

## 4. 전체 매핑 구조 설계

### 4-1. 연결 입도 (정밀 매핑)
- 거시 단계뿐 아니라 **세부 활동까지 정밀 연결**
- 연결 레벨 : `CJM L3/L4(고객 액티비티)` ↔ `SBF 3Depth(실제 업무)` ↔ `BSS 화면`
- 모집단 규모 : CJM 약 700개 활동(L3 176 + L4 526) × SBF 약 400~500개 업무

### 4-2. 연결 방식 (단계축 + 다대다)
- **1단계 — 단계축 정렬** : CJM L1(6단계) ↔ SBF 1Depth 대응표로 매칭 범위를 단계 내로 한정
- **2단계 — 활동 의미매칭** : 활동명·업무명 기준 의미 연결, **다대다 허용** (한 고객 활동 ↔ 여러 업무, 그 역도 성립)
- **3단계 — BSS 자동 연결** : 매칭된 SBF 업무에 기존 화면맵핑(UI Pgm ID)을 자동 결합
- **신뢰도 표기** : 각 연결에 상/중/하 + 근거 부여 → 검수 우선순위 판단

### 4-3. 대상 범위
- **포함** : 고객접점 업무 전체 (고객여정 264 + 고객접점 운영업무 : 채널·상담·수납미납·오더풀필먼트·영업판매 등)
- **제외(여정 무관)** : 순수 백오피스 (약관 거버넌스·시스템 운영·회계 등) — 억지 매핑으로 인한 노이즈 방지

## 5. 생성·검수·운영 방식 (거버넌스)

- **초안 자동 생성** : 매핑 초안은 자동 생성(단계축+의미매칭) → 수작업 대비 대폭 단축
- **현업·CX 검수** : CX팀·현업이 신뢰도 높은 건부터 승인/수정/반려 (기존 CJM '검토_요청' 큐 방식 재사용)
- **단일 출처(Single Source of Truth)** : 확정 매핑은 한 곳에서 관리, CJM/SBF 변경 시 연동 유지
- **버전 관리** : CJM·SBF 모두 개정되므로 매핑도 버전·이력 관리 대상

## 6. 활용 시나리오 (연결의 가치)

- **① CX 개선 → 실행 연결** : 고객 페인포인트 발생 단계 → 책임 업무·조직·BSS 화면을 즉시 추적 → 개선 과제로 직결
- **② AX/시스템 과제 → 영향 분석** : 특정 업무·시스템 개편 시, 영향받는 고객여정·KPI를 역추적
- **③ KPI 책임 연계** : 여정 KPI 부진 → 연결된 업무·조직·시스템으로 원인 귀속
- **④ 전사 공통 언어** : 마케팅·상품·IT·CS가 "고객여정 ↔ 업무 ↔ 시스템"을 같은 지도 위에서 대화

## 7. 추진 로드맵

| 단계 | 내용 | 산출물 | 기존 시스템 영향 |
|---|---|---|---|
| **Phase 1 (PoC)** | 전체 매핑 초안 자동 생성 + '미납' 사례 end-to-end 검증 | 매핑 초안 테이블 · 로컬 뷰어 · 커버리지 리포트 | **무영향(독립 산출물)** |
| **Phase 2 (검증·통합)** | 임원 방향 확정 후, 매핑을 관리 체계로 통합 + 검수 워크플로 | 통합 관리 화면 · 검수 큐 | 별도 협의 후 진행 |
| **Phase 3 (운영·확장)** | 정기 검수·갱신, KPI/조직 연계 고도화, 전사 활용 | 운영 프로세스 | 정식 운영 |

- ▶ Phase 1은 **기존 시트·사이트·시스템을 일절 변경하지 않고** 독립적으로 진행 → 리스크 없이 방향성 검증

## 8. 기대 효과

- 고객 경험과 업무·시스템 간 **단절 해소** → 개선의 실행 추적성 확보
- 흩어진 개선 요청을 **여정-업무-시스템 좌표**에 정렬 → 우선순위·책임 명확화
- CJM·SBF·KPI 자산을 **하나의 연결 지도**로 통합 → 중복 투자·사각지대 축소
