# CJM ↔ SBF 매핑 체계 설계 (Phase 1 PoC)

- 작성일: 2026-06-10
- 작성: CX팀 / Claude Code
- 상태: 설계 확정, 구현 계획 수립 대기

## 1. 배경 & 임원 요청

SK텔레콤은 채널/NOVA(기간계 BO) 직원 업무를 **SBF(SKT Business Framework, v2.0)** 로 정의했다(업무 목록). 별도로 CX팀은 전사 표준이 되는 **고객표준여정(CJM, L1~L4)** 과 여정별 KPI를 현업 의견으로 확정했다.

담당 임원 요청: **CJM과 SBF를 연결·매핑해서 관리할 수 없는가.** 예) 고객이 "미납 처리"를 하는 CJM 단계가 있으면, 이를 SBF 업무로 전환했을 때 BSS의 "미납 청구 조회/처리" 업무와 연결되도록.

> 임원의 정확한 의도는 아직 확정 전. 그래서 **무겁게 통합하기 전에, 미납 사례로 끝까지 연결되는 PoC를 먼저 만들어 방향을 검증**하는 것이 본 설계의 목적이다.

## 2. 핵심 분석 (왜 이 매핑이 가능한가)

1. **CJM = 고객 관점**("무엇을 경험/하려는가"), **SBF = 업무·시스템 관점**("무슨 업무를 수행하는가"). 지금은 둘이 따로 관리된다.
2. **SBF는 이미 "여정 축"을 내장**한다. SBF 1Depth에 `1.탐색·2.회원·계정·3.계약·개통·4.배송·설치·5.이용·변경·7.청구·수납·8.채권·조정·9.해지·잔존` 같은 번호형 단계가 존재 → CJM L1과 평행 구조. 임원의 "미납" 예시는 `8.채권·조정`/`수납·미납 운영`에 해당.
3. **SBF → BSS 화면 매핑은 v2.0에 이미 존재**한다(`3.SSF(L3)-화면 맵핑` 시트, UI Pgm ID = 실제 BSS 화면코드, 약 10,000행). → **우리가 새로 만들 것은 "CJM ↔ SBF" 다리 하나뿐**이고, "SBF → BSS"는 자동으로 따라온다.
4. KPI 시트 출처에 이미 "NOVA SBF KPI"가 유입되어 있어, KPI 레벨에서는 SBF→CJM 연결이 이미 부분적으로 일어났다.

연결 사슬:

```
[CJM 고객단계] ──(이번에 만들 매핑)──▶ [SBF 업무] ──(v2.0에 이미 있음)──▶ [BSS 화면]
  미납 처리                            미납 청구 조회/처리              ZxxxBILxxx 화면
```

## 5. Phase 1 설계 (독립 PoC)

### 5.1 산출물 위치 & 입력
- 새 폴더 **`sbf-cjm-mapping/`** 하나만 생성. 기존 파일은 읽기만 하고 수정 안 함.
- 입력(읽기 전용):
  - CJM: `sbf/1.0 ver/SKT_고객표준여정 관리 시트 (CX팀) - 고객여정 Manager.csv`
  - SBF: `sbf/SKT_Business_Framework_v2.0.xlsx` → `0.Business Framework`, `3.SSF(L3)-화면 맵핑`

### 5.2 매핑 엔진 (초안 자동 생성 방식)
1. **단계축 정렬(crosswalk)** — CJM L1 ↔ SBF 1Depth 대응표를 먼저 정의해 매칭 공간을 단계 안으로 좁힌다. 초안 crosswalk:

   | CJM L1 | 대응 SBF 1Depth(주) |
   |---|---|
   | 인입 | 채널, CVM&CJM&C360, 상품(인지), 1.탐색(부분) |
   | 탐색 | 1.탐색, 상품, 상담&채널 |
   | 구매/가입/개통 | 3.계약·개통, 4.배송·설치, 가입/변경/해지·풀필먼트 운영, 영업/판매 |
   | 서비스 이용 | 2.회원·계정, 5.이용·변경, 7.청구·수납, 수납·미납 운영, 청구 운영, 상담 |
   | 유지 및 확장 | 5.이용·변경, CVM, 영업/판매 |
   | 이탈 | 9.해지·잔존, 8.채권·조정 |

   (구현 중 정밀화)
2. **단계 내 의미매칭** — CJM L3/L4 활동명 ↔ SBF 3Depth 업무명을 키워드·의미로 연결. **다대다 허용**(한 CJM 활동 ↔ 여러 SBF업무, 그 역도 성립).
3. **BSS 자동 연결** — 매칭된 SBF업무 → 화면맵핑 시트의 UI Pgm ID / 화면명을 join해 자동 첨부. (join 키: 업무명/L3 — 구현 시 `2.SSF(L3)-IA 맵핑` 시트로 키 정합성 확인)
4. **신뢰도 표시** — 각 연결에 상/중/하 + 근거 한 줄(매칭 방식: 단계축+활동명 일치/키워드 일치/추정 등).

### 5.3 결과물 2종
- **(A 관리 테이블) `mapping_draft.csv`**
  컬럼: `CJM_L1 | CJM_L2 | CJM_L3 | CJM_L4 | CJM노드ID | SBF_업무ID | SBF_1Depth | SBF_2Depth | SBF_3Depth(업무명) | BSS_UIPgmID | BSS_화면명 | 신뢰도 | 근거 | 검수상태(승인/수정/반려) | 검수메모`
  → CX팀이 그대로 열어 검수. (검수 컬럼은 비어 있는 채로 제공)
- **(B 대시보드 느낌) `mapping_viewer.html`**
  - **로컬에서 여는 독립 정적 페이지**(배포하지 않음). 외부 의존 없이 단일 HTML.
  - 좌: CJM 여정 단계(L1→L2→L3/L4) 트리. 단계 클릭 → 우: 연결된 SBF 업무 목록 → 각 업무 아래 BSS 화면.
  - 신뢰도 뱃지(상/중/하), 매칭 안 된 노드 표시.
  - 데이터는 `mapping_draft.csv`를 임베드하거나 같은 폴더 json을 읽음.

### 5.4 미납 쇼케이스 + 커버리지 리포트
- **미납 end-to-end(정밀 검증):** `서비스 이용 > 요금/납부 관리 > 미납 처리` → SBF `수납·미납 운영 / 8.채권·조정 : 미납 청구 조회·미납 청구 처리` → BSS 화면까지 사람이 직접 검증해 데모 품질로 확정. viewer에서 기본 강조.
- **커버리지 리포트(`coverage_report.md` 또는 viewer 내 1면):** CJM 노드 매칭률, 신뢰도 분포, **매칭 안 된 빈칸 목록**(임원과 논의할 갭).

## 6. 비범위 (Phase 1에서 안 하는 것)
- 라이브 구글시트/GAS/대시보드 수정 및 Vercel 배포. (검증 후 Phase 2에서 별도 논의)
- SBF 원본 전체를 시트에 적재하는 것. (참조용으로만 읽음)
- 자동 동기화(추후 통합 시점에 설계)

## 7. Phase 2 (검증 후, 본 설계 범위 밖 — 참고)
PoC로 임원 방향이 확정되면, 매핑 데이터를 기존 아키텍처(구글시트 신규 탭 + GAS + CJM 대시보드 패널)로 통합. 검수는 기존 `검토_요청` 큐 패턴 재사용.

## 8. 성공 기준 (Phase 1)
1. CJM 여정의 임의 단계를 골랐을 때, 연결된 SBF 업무와 BSS 화면이 보인다.
2. 미납 사례가 CJM→SBF→BSS로 끊김 없이 연결되어 데모 가능하다.
3. CX팀이 `mapping_draft.csv`만 보고 각 연결을 승인/수정/반려할 수 있다.
4. 어디가 비었는지(갭) 한눈에 보여 임원과 다음 논의가 가능하다.
5. 기존 시트·사이트·배포에 어떤 변경도 가하지 않았다.
